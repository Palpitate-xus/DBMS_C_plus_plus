# R273：页锁测试丢弃已观察到的等待快照

状态：修复测试轮询的双快照竞态，增加固定回放及逐调度观测；不修改生产锁实现，不关闭历史页锁失败、DROP 清理失败或原 273 项总清单。

## 缺陷与修改方法

| 问题 | 影响 | 修改方法 |
| --- | --- | --- |
| 循环条件已经看到等待边，退出后又调用一次 `getLockWaits()` 决定 `waited` | 两次快照之间等待边消失时，误报“从未等待”；随后字节比较可能没有运行，却再次报告页面检查失败 | 保留使轮询退出的实际正快照，不用后续快照覆盖 |
| worker 已完成或循环已因期限退出，仍额外读取等待快照 | 可能把退出后才出现的等待误当作已观察到的事件 | 退出后不再采样；无正快照就返回 false，未降低等待断言要求 |
| 原失败标签没有场景号及关键观测值 | 不能区分真实字节不等、未运行比较、等待边丢失及最终清理失败 | 输出场景号、workers、holder 类型、outcome、目标页、采样次数/正采样次数、最终采样、完成状态、是否运行字节比较、fetch/字节结果及 SQLSTATE |

`getLockWaits()` 是即时快照。页锁等待重试会移除并重新发布等待边，超时/完成也会移除边；两个读取不能被当作同一事件。
修改仅在既有 `tests/vacuum_page_lock_test.cpp`：提取本地可回放的轮询 primitive，保存正快照，并补充测试与日志。
原 119 个控制、八个真实调度、200 ms 锁超时、5 秒挂起保护及 1 ms 轮询间隔保留；取消、页字节、行值、调用者锁状态、最终 DROP 断言均保留。
64 个回放有独立 footer 和失败计数；原 119 控制的 reach 检查不改，程序只要任一组失败就返回非零。
