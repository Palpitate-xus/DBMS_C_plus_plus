# R323：CHAR 数组构造错误套用长度 1

状态：元素值截短已修正并完成下列有限验证；仍有独立严格差异 OPEN，不代表全部数组功能完成。

## 问题与影响

`SELECT ARRAY['abc '::character(4)]` 应保留完整字符及尾随空格；旧实现
却在隐式元素转换时再次套用显式 CHAR 默认长度 1，输出 `{a}`。
`ARRAY[c]` 对存储 CHAR 列也复现；客户端文本及二进制数组中的值都会
被截短。嵌套数组需要保持相同的无 typmod 元素转换规则。

## 修改方法与边界

在 ARRAY 构造器内将 CHAR/BPCHAR 公共元素类型的转换目标设为已有
`pg_catalog.bpchar` 无长度输入路径；标量与嵌套子数组均采用该目标。
不改变显式 `CHAR`/`CHAR(n)` 或数组的显式转换，也不更改其他类型的
转换、比较、存储和物理身份规则。原 BIT 专用分支保持不变。
R322 按用户要求暂缓；其 FLOAT8/ABS/.inc 缓存改动不属于此修复。
