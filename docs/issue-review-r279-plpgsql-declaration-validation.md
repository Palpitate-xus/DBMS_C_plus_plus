## 已观察的问题

实际 PostgreSQL 18.6 在创建函数时拒绝未加引号的 PL/pgSQL 保留字声明、
部分不合法的 FOR 变量、缺失类型和不合法的函数体结构。当前产品会先接受创建，
部分错误直到执行才暴露，部分结构错误则被忽略。`CREATE OR REPLACE` 的错误
优先级和失败时保留旧定义也需要单独验证，不能用运行时拒绝代替创建时校验。

保留字与普通 SQL 关键字不同；双引号名称、已声明变量、参数和嵌套作用域
不能用一个全局关键字黑名单处理。`check_function_bodies` 当前也未支持，
不能声称已经具备其开关语义。

## 候选方法（未实施）

将现有解释器的语法解析提取为不执行的校验入口，保留 PL/pgSQL 自己的关键字
分类与词法作用域；在重复定义、参数/返回类型等已有检查之后、发布新定义之前
调用它。不得运行函数体、默认值、查询或用户函数来验证语法。公共头变化后必须
重新编译依赖，不能混用旧头对象。该方法仍不等于完整 PostgreSQL 编译器或类型检查。
