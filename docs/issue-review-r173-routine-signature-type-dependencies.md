## 实际问题与修改方向

| 问题 | 实际影响 | 修改方法 |
| --- | --- | --- |
| DROP DOMAIN/复合类型 RESTRICT 不检查外部函数的参数、返回类型 | 有依赖时仍成功删除类型；重复删除才报缺失对象 | 在首次修改前读取真实普通函数声明，按创建时的 schema/name 身份建立依赖 |
| DROP SCHEMA CASCADE 遗漏其他 schema 的签名依赖 | 外部函数保留失效类型引用 | 把经过核验的外部依赖加入同一事务删除计划，保留无关同名对象 |
| 候选读取器把声明内部 CR 一概判为损坏 | 可能拒绝旧版实际允许的域名声明 | 保留真实生产者支持的字节；不能用 composite 的标识符限制推定 domain 同样受限 |

普通函数保存在独立 sidecar 中，不能假定 pg_proc/pg_depend 已完整包含这些边。
应使用真实事务所有权和实际声明，不能执行函数体、猜测 TEXT、按当前 search_path 重解释旧身份，
也不能在首次删除后才检查依赖。直接依赖 CASCADE 的完整兼容仍未实现；候选曾选择显式拒绝并保持不修改。
