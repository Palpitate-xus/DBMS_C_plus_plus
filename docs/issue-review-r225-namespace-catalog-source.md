# R225：pg_namespace 的真实 typed 查询源

状态：三个实际字段的有限查询源已通过两侧完整专项与相关回归；不是完整 pg_namespace/ACL 或全部总清单完成。

## 问题与修复

旧绑定器和执行接收器没有 pg_namespace 源，pg_class JOIN pg_namespace 的实际 OID
检查返回 42P01；旧无数据库参数的 queryPgCatalog 分支还把数据库目录名当作模式行。
R224 完整 196 项的 22 个 OID 关联检查因此失败，不能用原生目录通过代替 SQL 通过。

现在共同描述提供真实 PgNamespaceRow 的 oid/nspname/nspowner 三列，类型为 OID26/
NAME19/OID26。执行从调用者实际数据库的 CatalogService 元数据快照复制行，复用既有
DDL 所有权/提交可见性边界，不枚举数据库目录造行，不构造固定 OID，不改写测试 SQL。
Main 的 statement-owned 读取/关联/CTE/派生接收器与独立引擎的原生 prepared plan 都有
对应数据源。网络 Parse 在发布语句前做同一个纯绑定分析，Describe 不执行数据源或例程。

旧无数据库参数的文本 API 不能表达模式所属数据库，现在明确报 0A000；真实 typed
查询使用显式数据库，测试覆盖两数据库隔离及不同的实际 owner/OID。

## 未实现边界不能伪装成功

PgNamespaceRow 尚无 nspacl，不能造 NULL 或让 SELECT * 返回缩短的 PG 表结构。
绑定按实际源身份拒绝完整行 wildcard、ACL 引用、四列源别名、需要完整结构的 NATURAL
JOIN 及 ACL USING 键，均为 0A000；WHERE FALSE/LIMIT 0/嵌套源也不能绕过。
仅给已显式投影的真实字段做外层 star 是合法的；COUNT(*) 不是行 wildcard。
保留 SQL 作用域、错误别名和歧义检查，三列重命名不能绕过完整结构限制。

保留项目既有的未限定同名 public 用户表优先行为，六项专门检查对此做回归；这不是
PostgreSQL 隐式 pg_catalog/search_path 遮蔽规则的完整兼容性证明。
R210 默认 GUC/有效角色展开、R217 通用 CTE/派生 Describe、完整 ACL 等暂缓项不恢复。
FROM 探针只检查真实 FROM/CTE/set 树；没有把所有表达式子查询和所有 SQL 执行形状一并接管。
