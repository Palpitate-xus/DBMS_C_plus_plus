# R262：大对象跨管理器大小缓存失效

状态：普通C++ API顺序可见性问题已修复并完成有限验证；STO-07及原273项总清单未整体完成。

## 缺陷与修改方法

| 缺陷 | 影响 | 修改方法 |
| --- | --- | --- |
| size()仅查构造/本地写入时的sizes_缓存 | 另一管理器扩写、截短、导入、删除或后创建对象后，read()已看到磁盘现状，size()仍返回旧值 | 打开当前普通对象文件，按fd的fstat结果返回实际长度；确认ENOENT返回0 |
| 单纯改为所有打开失败都返回0，会破坏既有失败语义 | 删除失败、对象路径暂不可读时，既有调用方会丢失已知大小 | 对非ENOENT打开失败或无有效stat结果保留原缓存值；不清除缓存，不把错误伪称为已确认的空对象 |

生产只修改LargeObject.cpp的size()。没有新API、类布局、头字段、SQL入口、文件格式或
事务/WAL改动。保留旧接口：未知/无效ID及确认不存在返回0；无法读取元数据时返回
本管理器原先已知值（未知则0）。因此该size_t接口仍不能区分空对象与部分错误，不能
把错误回退值作为当前大小或可读性证明。正常查询新增open/fstat/close开销，未做性能保证。

## 旧新对照与回归

同一原生夹具在Root工作区与纯提交投影各完整46控制，旧实现两侧均30失败、退出1，
没有setup错误；最终修复两侧均46通过、零失败、退出0。失败控制数不是独立bug数量。

36个peer控制为18种操作乘同进程独立管理器/真实fork子进程；包含扩写、截短、扩长、
清空、长/短/空/等长导入、删除、后创建、稀疏写、peer改变后observer覆盖/空写，以及
read与size和新管理器的一致性。另10控制保留无效/未知ID、空对象、失败的越界写入/
截断、缺失导入及无关对象不干扰。子进程退出后父进程才检查，是顺序跨进程可见性，
不是同时写入、线程安全、事务快照或crash/power-loss验证。

首次候选虽通过新46项，但完整24次既有回归中两侧drop_failure均失败（22通过/2失败）：

或修改该断言。最终候选保留错误回退，再将原24次全部重跑，实际全0。回归包括两侧
各11个既有普通LO原生及phase8_10；原断言与60秒deadline不变。一次V2运行器因重用
不可覆盖的V1日志名称在首项运行前停止，随后使用唯一V2名称执行完整24次，旧日志不覆盖。

最终定向ASan/UBSan同时插桩LargeObject.cpp和新夹具，完整46通过，无弱化选项。
fork helper使用_exit，不宣称每个子进程执行了LSan退出扫描。不是全库sanitizer或TSan。
两侧新原生加24次既有回归共26次实际运行全0，另有一次sanitizer；不等于全库存验收。

每侧fresh编译本项生产CPP、新原生和12个既有原生TU。普通LO测试只链接真实LO对象；
