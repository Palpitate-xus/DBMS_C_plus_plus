# R266：大对象CREATE分配失败后发布未返回的文件或消耗空闲ID

状态：候选ID的可抛准备已前移，普通分配异常不再发布未返回文件或跳过该空闲ID；STO-07及原273总清单未整体完成。

## 缺陷与修改方法

| 缺陷 | 影响 | 修改方法 |
| --- | --- | --- |
| 新文件已O_EXCL创建、同步并关闭后，才构造父路径或分配sizes_节点 | bad_alloc向调用者传播，但新空文件已存在且ID未返回 | 对每个候选ID先准备filesystem::path、父目录及待发布map节点，再创建文件；成功后以同分配器node handle插入，无需新分配 |
| nextId_在路径/缓存准备之前推进 | 准备阶段内存失败也跳过仍可用的ID，int上界可能被提前耗尽 | 所有可抛准备成功后才推进候选ID；保留真实I/O失败原有的计数和返回行为 |

生产只修改LargeObject.cpp的create()。EEXIST沿用已准备路径与节点，不再在持有peer
对象fd时分配缓存节点；已有缓存条目直接更新值。新对象仍在原先file fsync、close、
directory fsync全部成功后发布缓存及返回ID；真实I/O错误的清理顺序不改。
每个候选迭代可能需要准备内存，前一迭代可观察并缓存peer对象；本项不声称整个调用
的所有内存状态逐字节回滚。保证针对分配异常不丢失待分配空闲ID、不产生本调用未
返回的文件；不是事务/WAL语义。碰撞路径的预准备有成本，未作吞吐或无开销保证。

没有新公共头、API、类布局、文件名格式、Main、WAL、CLOG或全局registry改动；其他
生产函数保持不变。INT_MAX控制只针对本项目现有int ID边界，不扩展ID或offset支持范围。

## 既有fd回归的诚实适配

既有R264测试的CREATE碰撞分配点现在发生在打开peer fd之前。保留原51个控制：该
场景原先的6个故障序号控制在没有fd-live分配时验证正常结果及关闭/重试，不删除
这些控制，也不声称注入了不存在的失败；其他入口仍要求原真实分配失败及恰好一次
close，文件/内容/fd/重试断言保留。适配后的夹具先在旧接受库两侧各51通过、12点；
新库两侧各51通过、9点，准确记录3个已消除的fd-live分配点。新552矩阵则真实注入
CREATE准备阶段的失败，不能以这6个正常控制代替准备阶段验收。原R264历史日志不改写。
