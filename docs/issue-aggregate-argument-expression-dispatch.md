## Real failure and consumer

The unchanged numeric control
`SELECT SUM(CASE WHEN n > 0 THEN 1 ELSE 0 END) FROM args`, with n = 1, 2,
SQL NULL, -1, returned 0 with a TEXT/25 descriptor instead of 2 with INT8/20.
The same expression followed by `+0` already reached the engine's typed
aggregate-expression graph and returned the correct value and type. Bare
COUNT(CASE ...), arithmetic/cast arguments and empty SUM inputs had the same
dispatch defect. Boolean reducers substituted unquoted stored data into SQL,
silently skipped failed evaluations and returned SQL NULL for real text
comparisons. Empty text and the text "NULL" are not SQL NULL.

The legacy top-level aggregate receiver understands bare columns and some
special arguments, but not an arbitrary retained CASE/cast/expression input.
Failed numeric parsing became the initialized zero, and its descriptor fallback
was TEXT. The existing typed reduction graph already owns declared argument
types, NULL flags, FILTER-before-input demand, per-occurrence states and final
result types. The new frontend boundary selects that real owner rather than
quoting row bytes or fabricating a result descriptor.

## Changed boundary and limits

The frontend uses a role-only parse of the original statement, retains each
eligible target's actual source interval and original argument/FILTER syntax,
and passes it to the existing `queryExpr` reduction graph. Actual aliases are
decoded once; qualified builtin headers use their resolved local names.
Protocol descriptors still use the real declared column/function input types,
including nullable inputs and Parse/Describe without argument execution.

The selected WHERE receiver constructs OR/AND branches from actual Boolean AST
nodes. Real source-column/bare-literal comparisons keep their physical compact
index receiver. Other leaves use a parenthesized AST representation with actual
source-bound columns, typed literals and CAST modifiers. Thus TRUE/FALSE/NULL,
NOT and grouped Boolean branches cannot disappear during legacy token conversion.
All qualifying physical RIDs are unioned before one reduction; repeated branches
do not repeat a volatile input and reduced sentinel RIDs are not deduplication
keys. Original FILTER and LIMIT-zero demand boundaries remain intact.

The scope is a simple table source, no SQL child/query/row/quantified argument,
CTE/set/group/HAVING/window/locking/global-ORDER envelope, or actual SRF. There
must be an expression aggregate argument; plain-column reducers stay with their
existing receiver. Existing within-call ORDER grammar has a synthetic argument
and remains with its established owner. Actual qualified stored routines and
unqualified stored names are not assigned a builtin aggregate role by spelling.
No global predicate adapter, default locale, scalar planner aggregate gate,
catalog type identity, WAL, hash-index or public header was changed.
