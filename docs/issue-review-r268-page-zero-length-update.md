# R268：零长度堆页更新成功后产生无效页面

状态：已修复原生页面 API 的零长度更新准入错误。仅关闭这一页面不变量缺陷；STO-03 及原 273 项总清单仍未整体完成。

## 缺陷与修改方法

| 缺陷 | 影响 | 修改方法 |
| --- | --- | --- |
| `PgPage::update()` 把长度 0 当作原位缩短更新，清空旧数据后仍返回成功并写入校验和 | 产生 `LP_NORMAL`、长度 0 的槽；`get()` 返回空行，但同一实现的 `isValid()` 拒绝该页。`PageWrapper::update()` 同样受影响 | 与既有 `insert()` 的非空元组约束一致，在更新入口拒绝长度 0；在任何页面字节、槽、校验和或输出参数发生变化之前返回 false |

只修改 `PgPage.cpp` 更新入口的条件及说明注释；非空更新、压缩、重定向、磁盘格式、头文件、布局及公共签名均未改动。
无输出参数的重载也经相同入口拒绝；空更新失败保持原有行及调用者的输出槽号不变。
这是原生页面 API 的真实不变量问题，不声称已经复现某条 SQL 能产生该页：当前 `TableManage` 通常传入带非空头部的编码元组，SQL 空字符串并不等于长度 0 的物理元组。

## 旧新对照

同一夹具在 Root 已接受源码投影及纯提交投影各运行完整 280 个固定控制。
旧实现各 160 失败、退出 1；全部 160 个空更新控制失败，另外 120 个非空控制通过，没有 `CONTROL_ERROR`。
修复后两侧各 280/0、退出 0；输入、断言和矩阵保持一致。

| 控制族 | 数量 | 内容 |
| --- | --- | --- |
| 4 个调用形式 ×5 个旧长度 ×4 个余量 ×2 个目标槽位置 | 160 | `PgPage` 有/无输出参数、`PageWrapper` 有/无输出参数；长度 1/2/31/256/1024；余量 0/1/7 字节及宽松空间；首槽及前有存活邻居的后续槽 |
| 4 个调用形式 ×5 个旧长度 ×2 个槽形状 ×3 个替换长度 | 120 | 非空单字节、等长、增长一字节；有/无更早可复用槽，检查增长后的真实返回槽号、邻居和完整值 |

空更新被拒绝时比较整个 8 KiB 页面及输出哨兵值，并检查原行、邻居、空闲量、槽数、页身份、LSN、链指针、校验和和有效性。
每个成功拒绝后再做等长非空更新，确保满页也能正常重试。旧实现发生破坏后不手工修复该页来制造通过。
数据包含二进制字节；非空控制同时覆盖更早空槽被增长更新复用的情况。
