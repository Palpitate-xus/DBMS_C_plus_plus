# R344：TIMETZ 非空二进制结果缺少编码

状态：显式数字 offset 的真实 TIMETZ 二进制输出已修复并完成下列有限验证。
不是整个 TIMETZ 输入／值／binary 参数、所有协议角色或原 273 总清单完成。

| 缺陷 | 原因 | 修改方法 |
| --- | --- | --- |
| 非空 TIMETZ 结果返回 0A000 | 二进制分派遗漏真实内建 OID1266 | 输出 8 字节本地时钟微秒和 4 字节有符号 seconds-west，全部网络字节序 |
| 时区符号及秒数不能丢失 | TIMETZ 并非 UTC timestamp，offset 也不是分钟字段 | 保留 local clock，独立校验正负数字 offset、15:59:59 边界与秒级 offset；不经 double |
| TIMETZ 数组非空元素同样缺少编码 | 原真实 builtin array producer 递归调用缺失的标量 codec | 复用原 1270→1266 身份与数组递归，保留维度、下界、NULL、12 字节元素 |
| 两处旧测试断言 TIMETZ 不支持 | 功能补齐后旧明确拒绝断言已过时 | 按实际 PostgreSQL 字节改成成功控制，不删除断言；TIME 原生另加 82 项，总计 203 项 |

只修改 PostgresProtocol.cpp、既有两个原生测试、协议驱动／冻结参考、
注册和本文，共七路径。不修改 Main、NetworkServer、evaluator、公共头、
binder、存储、规划器或 binary 参数接收器；当前 R350 高精度警告按用户
最新要求跳过，其他既有跳过项也不恢复。codec 不补 CAST 精度舍入，
不把无 offset 的文本猜成会话时区，不把文本格式冒充 binary。
错误或不完整载体拒绝发送整条 DataRow，之前列的缓冲不得泄露部分帧。

## 实际验证

修复前用全新私有 PostgreSQL 18.6 cluster 采集 2563 请求，再用独立新
cluster 严格重放实际 exit0。原 2362 请求与期望精确前缀；新增 201 项覆盖
正负／秒级 offset、0/24h、微秒、NULL、schema／引号／长名称、标量与
多维／显式下界数组、文本参数、各 CAST 精度以及非法 clock／zone。
参考实测拒绝 6 位紧凑 zone（如 -083045），故本编码器不将其当成功。
首次 strict helper 因缺少私有 socket 目录而启动失败；原日志保留，
修正验证环境后用另一全新 cluster 完整重跑，不改变 golden 或产品候选。
原始采集的退出 0 仅表示采集完成，不等于工程语义全部通过。
