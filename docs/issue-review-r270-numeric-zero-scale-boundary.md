# R270：零值在 NUMERIC scale 1000 被误报溢出

状态：修复现有解析 scale 范围内零值的错误准入；非零值及更大范围的精度/scale 问题仍开放，TYPE-01 和原 273 项总清单未完成。

## 问题及修改方法

| 问题 | 影响 | 修改方法 |
| --- | --- | --- |
| `withScale()` 在规范化零之前，把显示用尾零计入有效数字预算 | `0::numeric(1000,1000)`、`round(0::numeric,1000)` 报 22003，而值相同的 `0.0` 成功；影响参数、列写入及更新 | 对有限零值且目标 scale 不大于既有解析上限 1000 的情况，保持单个零数字，直接设置非负显示 scale；其余路径继续原有检查 |

生产仅修改 `Numeric::withScale()`。NaN/Infinity 原有早返回不变；非零值、目标 scale 大于 1000、负 scale 舍入、头文件、参数签名、类布局及磁盘格式不改。
没有增加全局精度上限，也没有取消 INT_MAX 等目标值的既有拒绝检查。目标为负时，零仍返回 scale 0。

PostgreSQL 18 的显式 NUMERIC 精度上限为 1000，允许 scale 大于 precision；无约束 NUMERIC 的更大范围不能混同这个声明上限。[官方数值类型说明](https://www.postgresql.org/docs/18/datatype-numeric.html)
实际参考端严格核实为 `server_version_num=180006`；没有用项目输出生成 PostgreSQL 期望值。

## 真实旧新对照

同一原生夹具两侧各完整 18217 控制：旧版各 6 失败、退出 1，新版各零失败、退出 0。
失败的六种零来源都在目标 scale 1000 被误拒绝；不将六个控制记为六个独立缺陷。

| 原生控制族 | 数量 | 范围 |
| --- | --- | --- |
| 18 种零来源 ×0–1000 的全部目标 scale | 18018 | 默认、整数、相消、科学计数，以及正负文本零的七种输入 scale |
| 18 种零 ×4 个负目标 | 72 | 包括 INT_MIN；精确文本、scale、精度、符号、有限标签及源对象不变 |
| 18 种零 ×5 个更大目标 | 90 | 1001/1500/1999/2000/INT_MAX，保留旧预算准入行为；不是更大范围的 PG 兼容通过 |
| 非零边界及舍入 | 10 | 正负小数、最小受测小数、进位、负 scale；保留已知非零精度限制的观测控制 |
| NaN/±Infinity ×9 个目标 | 27 | 特殊值不被零路径吞掉 |

首次夹具把预期拒绝条件放在短路表达式前面，导致一个非零拒绝控制没有调用被测方法而失败；原 7 失败日志和可逐字节重建的首版夹具已保存。
在任何生产修改前修正为实际调用方法，再验证拒绝；修正后的完整旧矩阵两侧各 6 失败。此后旧、新夹具字节及 18217 控制保持一致，没有删控制或弱化断言。

永久协议边界夹具在真实 PostgreSQL 18.6 完整 63/0；旧项目两侧各完整 64 控制、16 失败，修复后各 64/0。
项目额外一个 CHECKPOINT 控制用于关闭原进程、在同一私有目录启动新进程后重读；没有重启或 CHECKPOINT 共享参考数据库。
控制包含 CAST/ROUND、scale 大于 precision 的零值、NULL/特殊值、有效非零值及正确的 22003 拒绝、text Bind、text/binary NUMERIC 返回值、OID、列 typmod、INSERT/UPDATE、完整千位小数及持久化重读。
参考表采用本次生成的唯一名字，并在事务结束时回滚；不修改参考端既有表。

新增 helper 由原已注册 `numeric_zero_scale_protocol_e2e_test.py` 在原有全部语句之后调用；原有语句、断言及完成条件保留，不绕过注册或默认测试发现。
