# R329：数组连接的隐式元素转换误用显式长度默认值

状态：隐式数组值转换已修正并完成下述有限验证；剩余独立错误与总清单仍未完成。

`ARRAY[CHAR(4)] || ARRAY[CHAR(4)]` 的元素被截成单字符，BIT数组也需
核对相同隐式转换路径。应保留真实共同元素类型和无typmod转换，不能
把它当成显式CHAR/BIT默认长度1；显式CAST仍必须保留自己的长度规则。
保留NULL、维度/下界、真实OID、参数及一次求值，不能从行值猜描述符。

实际PG18.6先独立采集268，再扩展304请求（原268精确前缀），覆盖
操作符、函数正反控制、混合类型函数准入、真实表行、参数、空输入、
文本/二进制与序列效果。所有请求、原始帧、完整严格签名和失败均保存。
新原生56个SQL的期望来自实际PG，另有运行期NULL载体和一次求值控制。
不把混合类型函数或既有Bind规划阶段问题自动算作本项已修复。

## 实现和实际验证

ARRAY操作符的输入和真实数组函数的结果转换现在保留隐式上下文，
使用已求值RuntimeCell，不重新执行操作数，也不把它伪装成规划常量。
无modifier的隐式CHAR/BIT数组使用真正无长度默认值的物理输入类型；
显式CAST及真正的元素modifier仍使用原规则。数组元素转换保留实际
源类型，因而BPCHAR到TEXT/VARCHAR能正确处理尾空格，不能把它当UNKNOWN。
不从值、别名猜类型，不更改绑定器、网络、Main或公共头。
