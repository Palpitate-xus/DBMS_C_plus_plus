# R269：Numeric 默认零与显式零的状态及运算不一致

状态：统一零值构造及精度字段，只修复构造路径导致的不一致；不宣称所有零值操作及 scale 边界均已完成。TYPE-01 和原 273 项总清单仍未整体完成。

## 缺陷与修改方法

| 缺陷 | 影响 | 修改方法 |
| --- | --- | --- |
| 默认构造不初始化数字向量，`sign()` 把空向量视为正数 | 显示为 `0`，却不等于显式零；比较、负号、涉及特殊值或除法的运算与文本零不同 | 默认构造委托给现有整数零构造，正常构造完成后不再暴露空的有限数值表示 |
| 整数零构造提前返回，未设置 `precision_` | `Numeric(0).precision()` 为 0，而文本零为 1；精度限制操作会继续保留该差异 | 零分支显式设置精度为 1，与数字 `{0}` 及解析后的规范零一致 |

不修改 `sign()` 来掩盖空状态，也不增加另一个对外可见的有限零哨兵。生产改动仅为头文件一处构造委托、CPP 零分支一处精度赋值。
非零整数、字符串语法、舍入、算术算法、NaN/Infinity 构造、公共参数列表、类布局及磁盘格式均未改动。
默认构造现在可能分配一个数字的存储，不再具有旧隐式默认构造的 `noexcept` 性质；这不是无额外分配或无性能代价保证。
内部解析临时对象同样走规范零初始化，再经原有 leading-zero 清理和 normalize 路径处理。

## 固定旧新矩阵

同一夹具在 Root 已接受投影及纯提交投影各运行完整 2784 控制。
旧版两侧各失败 552 个，退出 1，分为 18 个状态失败、480 个运算差异、54 个方法差异；没有 `CONTROL_ERROR`。
新版两侧各 2784/0，退出 0，夹具字节、矩阵、断言及超时保持一致。552 是失败控制数量，不是 552 个独立缺陷。

| 控制族 | 数量 | 内容 |
| --- | --- | --- |
| 8 个构造来源 ×3 个传递方式 | 24 | 自动默认、花括号默认、array、vector、map 缺省元素、整数零、文本零、带 scale 的负文本零；直接返回、显式复制、移动赋值后的值 |
| 上述 24 个值 ×12 个操作数 ×9 个操作角色 | 2592 | 双向比较及四则运算；操作数包含正负数、不同 scale 的零、微小数、NaN 和正负 Infinity |
| 上述 24 个值 ×7 个方法角色 | 168 | 三种 scale、三种精度及平方根 |

状态检查包括精确文本、符号、精度、scale、有限/NaN/Infinity 标签、负号及与规范零的相等性。
运算及方法的对照是同一实现中相同显示 scale 的文本零，检查结果的全部上述公开字段及异常结果；这是零值表示的一致性验证，不是新的 PostgreSQL 数学 oracle。
不检查被移动源对象的值，不承诺一般 moved-from 状态已经规范化。

目前检查到的表达式及协议路径通常会在读取默认临时对象前给它赋值；未取得某条 SQL 直接读到未初始化零的复现。
本项确认的是公开原生 Numeric 类的值语义错误；不将原生除零的 NaN/Infinity 约定当作 SQL 的除零语义。既有 SQL 22012 检查不变。
