## 已确认的问题与候选方法

现有 Runtime/SQL 统计持久化在文件 rename 成功后仍分配、复制内存 baseline。
真实 C++ 分配失败可能让磁盘已经接收 delta，内存却仍使用旧 baseline；目录
fsync 失败也有同一发布/确认边界。后续重试可能重复累加。writer 抛异常的临时
文件清理另有问题。候选方法是预先分配路径及全部目标节点，区分未发布、已发布
但未确认持久、完全持久三个阶段，在已发布时确认内存 baseline，同时保留原 bool
对未确认持久化返回 false 的语义，并以 RAII 清理未发布临时文件。
该方法尚未纳入已接受版本，未修改文件格式或合并公式。
