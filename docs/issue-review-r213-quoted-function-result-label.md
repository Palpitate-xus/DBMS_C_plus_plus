# R213：带引号函数调用的默认结果列名

状态：本项有限列名修复已验收；不是原 273 项完成。

## 问题与修改方法

`SELECT "current_schema"()` 等未指定别名的函数调用，在 Simple 查询和
Extended 的 Parse/Describe 中可能得到 `?column?`、保留引号的名称或错误的小写名称。
函数执行成功不代表客户端得到正确的列名；按列名取值的客户端会受影响。

Simple 的无 FROM 查询已解析出表达式 AST，但默认列名分支没有将普通函数交给现有
`ExprHelper::projectionLabel`；后续字符串识别不能正确处理引号。
Extended 的描述路径则直接对 `call->funcName` 转小写，未解码 SQL 标识符。

首轮候选还留下真实表 `CAST(abs(n) AS text)` 和 `CAST(current_schema() AS text)`
两处 Simple 列名错误。完整 1,262 项首轮有 110 次失败，原日志保留，不算验收通过。
物理投影的手工 CAST 分支只保留裸列名，漏掉同为强名称的函数。
第二轮仅补充此分支的强名称继承，仍使用既有 AST，不改变 CAST 参数或求值路径。

修改将这些消费者接入已有 AST 列名规则。未加引号的名称折叠为小写；
带引号名称保留大小写，双引号转义解码，名称内部的点不是命名空间分隔符。
显式别名仍优先；外层运算符不继承内部函数名，直接 CAST 保留函数名。
不修改函数查找、执行、返回类型、参数或已解码的原生回调身份。
