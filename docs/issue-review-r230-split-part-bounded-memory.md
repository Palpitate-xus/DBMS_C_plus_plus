# R230：SPLIT_PART 的按需字段扫描

状态：有限内存开销修复通过；不是旧版结果语义错误或整个字符串需求族完成。

## 问题和修改方法

旧回调先将所有字段复制进 vector<string>，再取一个字段。正位置 1、负向越界以及
位置零报错都先建立完整列表。大量短字段时，单次临时分配显著大于原输入；普通
查询即使只需要首字段，也承担不必要的字段对象和复制成本。

现在正位置只扫描到目标；负位置按同一正向、不重叠的匹配规则计数，再定位目标，
末字段可直接使用计数时的偏移。只保存偏移/计数，不保存其他字段，辅助空间不再
随字段数量增长。输入/返回值及既有求值器本身仍可能分配，不能声称全查询零分配。
零位置仍为 22023，空分隔符仅在位置 1/-1 返回原文本；其他越界返回空 TEXT。

必须保留正向不重叠规则：例如 split_part('aaa','aa',-1) 返回 'a'，不能通过 rfind
从右侧找分隔符而错误返回空字符串。INT_MIN 先在既有 int64 位置域中计算，不对
32 位最小值直接取负。UTF-8、CHAR 去尾空白、NULL 位及实参求值/回调覆盖均不改。
不修改函数签名、绑定规则、公共头文件、存储格式、用户数据或其他已跳过模块。
