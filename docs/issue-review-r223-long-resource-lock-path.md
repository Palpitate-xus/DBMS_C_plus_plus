# R223：长资源名称导致锁文件名超限

状态：本项有限修复已通过两侧专项及相关回归；不是长限定表名或总清单完成。

## 故障与修改

锁管理器原先把完整资源名逐字节转为十六进制，生成
`.lockmgr/<kind>-<hex>.lock`。资源自身合法时，展开后的文件名仍可能超过
255 字节，导致打开锁文件失败。数据库调用者将其表现为 55P03、读计划打不开或写入失败。
表锁之外，行号、页号组成的资源名也会触发这个问题。

修复保留所有可容纳的旧文件名；仅超限时改用带 `sha256-` 标记的完整资源摘要作文件定位。
标记与旧十六进制格式分离，数据库目录和锁类别继续分离。
没有截断逻辑资源名、放宽互斥规则或忽略文件打开错误；内存锁和预备事务记录仍保留完整身份。
这是内部文件定位修复，不是 SQL 标识符长度扩展、认证/TDE 审查或完整锁子系统验收。
