# R228：OID / 内建 oid[] 的二进制发送

状态：typed send 的有限修复已验收；完整 100 项协议草稿尚有独立 R229 源定位错误，未接受。

## 故障与修复

OID26 已有真实目录行和结果描述，但 encodeBinaryValue 没有对应发送分支，实际有行时
请求二进制结果返回 0A000。新增真实内建 OID26 的无符号 4 字节网络序发送，使用
from_chars 严格检查整个规范输出字符串和 uint32 范围，不接受尾随垃圾、溢出或用户类型
按名字借用内建编码器。SQL NULL 仍由位图决定；错误仍在写出整行前返回，不写半帧。

首轮标量修复后，原生 94 项仍有 19 个 oid[] 控制失败：真实内建类型生产器遗漏
OID1028/_oid/typelem26 及标量的反向链接。仅在既有内建数组表增加这一项，使数组发送
复用同一 OID 元素编码器，不添加数组名字猜测/自定义 OID 退路，不重新实现 NAME。

本项是已有 typed 输出载体的发送边界，不修改 SQL OID 输入语法、参数接收、所有 OID
数组 SQL 声明/存储、类型依赖、历史用户目录或用户暂缓的 NAME 列 DDL；不是 TYPE/NET
整项或全部 273 项完成。负号、空白等非法测试是规范输出单元测试，不宣称 PG 输入拒绝它们。

## 实际验证

新增 tests/oid_binary_result_test.cpp 完整 94 项：15 个 uint32 边界向量（含 0、2^31、
UINT32_MAX）逐字节核对标量、文本、数组/NULL、混合列格式；另含空/全 NULL 数组、
负下界、多维数组、错误规范输出、伪装用户 OID、无半帧发送，以及无效字符串的真实 NULL。
