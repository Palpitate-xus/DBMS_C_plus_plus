# R232：成功关系锁升级保留嵌套持有计数

状态：成功升级分支的计数修复已验证；不是整个 TXN-07 或升级等待失败语义完成。

## 故障与修复

acquireLock 的升级路径先通过 releasePhysical 擦掉原 holderCounts，再由
acquirePhysical 把计数设为 1。原先多次 Shared/IS/IX 持有只剩一个计数；单次持有的既有升级转换约定则原本正确。
在多次持有后升级，单次 unlock 因而可能过早释放仍有其他 token 的关系锁。
已经没有 holder 时，rollbackToCheckpoint 不能重新创建它，单加检查点 guard 不够。

现在在成功升级前保存原深度，重新获得更强模式后恢复原深度。升级只是模式转换，
不增加新 token；单次持有仍可用一次 unlock 释放，多次持有则保留尚未释放的 token，
既有 checkpoint 能精确恢复原深度和原模式。未改变公共头文件、兼容矩阵、文件路径、
物理锁实现或用户数据；不是重写整个锁架构。

unlock 后真实其他线程的 DDL 阻塞或允许、checkpoint 后读者兼容/DDL 排斥及最后完整释放。

## 未关闭的分支

失败/取消的升级仍要独立核对：当前代码在等待更强模式前释放旧弱 token，失败时
没有恢复它。此次只修复重新获得强锁后的深度，不把成功分支用作失败分支证明。
后续应使用实际竞争者、失败/取消、多个同时升级者和进程物理锁转换逐分支验证，
再设计保留旧所有权的等待/失败协议。这是普通待审工作，不是用户新增暂缓。
