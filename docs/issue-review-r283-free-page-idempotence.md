# R283：重复释放堆页形成空闲链表循环

状态：修复同一 PageAllocator 中重复释放页的准入和重启时空闲链表校验。
不代表完整存储、事务、WAL 或原 273 条总清单已完成。

## 缺陷与修改方法

| 问题 | 已复现影响 | 修改方法 |
|---|---|---|
| `freePage(id)` 不检查页是否已在空闲链表中 | 再次释放头节点产生自循环，释放中间/尾节点产生环或改变链表；后续多个 `allocPage()` 返回同一个物理页，写入发生别名覆盖 | 由每个 allocator 维护空闲页集合，free/alloc 在原互斥锁内同步更新；重复释放在 fetch、改页、改头和写回前直接返回 |
| `open()` 只检查文件头，未校验整条空闲链 | 循环、越界链接以及指向非空页的空闲链被接受；旧问题能在关闭/重开后继续存在 | 打开时遍历并校验唯一、有限、在范围内且为空的页链，再发布集合；校验失败关闭缓存且不写回，不自动修复旧损坏文件 |

实际复现来自原生 PageAllocator API；没有证明某个现有 SQL VACUUM 调度会
重复释放同页。当前 VACUUM 会跳过已无槽的页，不能把本项描述为已确认的 SQL
数据丢失复现。API 在本项中确实曾返回重复页号，且完整字节验证观察到值覆盖。

集合在打开时重建、关闭时清空成员，不写入新磁盘字段。打开校验为 O(空闲页数)，
集合内存受已见空闲页峰值约束（清空成员不保证释放 bucket 容量），释放/分配
的集合查找为平均 O(1)。释放时在首个页修改前准备集合
节点，局部 pin guard 覆盖异常退出；没有声称已经故障注入所有分配/写回失败点。
类的私有布局变化，因此没有复用旧布局的生产、共享桩或测试对象。
