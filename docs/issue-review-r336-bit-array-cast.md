# R336：显式BIT数组转换准入与整数位宽执行错误

状态：本项转换准入及整数元素转换已修复；完成下述有限验证。
其他独立错误和所有用户跳过项仍保留，原273总清单未完成。

| 缺陷 | 原因 | 修改方法 |
| --- | --- | --- |
| 合法BIT数组CAST返回42846 | 共享元素类型检查缺少BIT↔VARBIT、BIT↔INT4/INT8转换边，带pg_catalog或引号的真实内建名字也未归一 | 只补真实目录转换关系，保留大小写／自定义schema边界；SQL NULL不能绕过非法类型检查 |
| 整数转BIT数组仍报错或取错位 | ARRAY把整数先转VARBIT；部分命名BIT目标先生成整字宽位串再截取高位 | 在现有绑定／表达式准备入口，为整数元素保留已有显式CastExpr及实际目标宽度，先完成INT→BIT，再构成数组；不提前求值、不重绑定／重复执行输入 |
| 只有准入修复会掩盖执行缺陷 | 初版新增用例仍有6处错误 | 保留初版日志与对象，不将能够执行但值错误的候选接受为修复；相同SQL／期望继续执行 |

BIT与INT2、VARBIT与整数，以及BIT与NUMERIC/BOOLEAN/BYTEA之间不存在的
转换继续返回42846，包括NULL输入。只有已有的整数到BIT显式边才新增
运行期元素转换；BIT/VARBIT共同类型及其他CHAR/NUMERIC/INTERVAL数组
上下文不借此改写。没有新增公共AST字段、常量折叠或规划载体，也不在
绑定时执行序列表达式。
