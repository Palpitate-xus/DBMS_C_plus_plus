# R215：拼接结果声明、专用输入和 VARBIT 类型传播

状态：本项结果声明及输入类型修复已验收；原总清单仍未完成。

## 问题和修改方法

`1 || ''`、用户整数函数或 NAME 会话函数参与拼接后，执行值已是文本，
但 `prepareBoundQuery` 的结果声明继承了左操作数类型。
Simple 会向客户端报告 integer/NAME；Extended 可能声明 text 却发送整数二进制字节。
按声明解码的客户端会误读，不能只比较终端显示。

根因在 `query_binding.cpp`：数组专门处理后，只有 internal-char 分支返回 TEXT，
其他标量继续落入通用二元表达式的“返回左类型”。

| 范围 | 发现及修改方法 |
| --- | --- |
| TEXT 结果 | 根据完整运算符结果登记 TEXT 的类型、OID 和 typmod，而不是继承函数、NAME、boolean、整数或 varchar/char 输入声明；保留真实表达式所有权。 |
| BYTEA 和位串 UNKNOWN 输入 | 真正的未知字面量或参数使用另一个已知专用操作数的输入 codec；为 BIT 家族选择不限长的 VARBIT，避免把多位字面量截成 BIT(1)。元数据阶段不执行函数或查询来猜类型。 |
| 位串拼接 | PostgreSQL 18 的 bitcat 返回 VARBIT（OID 1562），不是 BIT；同时纠正绑定器、静态推断和实际求值的返回类型，NULL 也一致。 |
| 下游位运算 | VARBIT 拼接进入取反、按位运算和移位后，这些运算仍返回它们自身的 BIT 声明，不能再次继承 VARBIT；显式 TEXT 与位串可选 TEXT 拼接，不被全部当作位串拼接拒绝。 |

数组仍使用现有 arrayConcat 绑定、元素公共类型和 NULL 数组规则。
结果通过现有目录声明回调取得真实数组 OID，而不是只返回一个数组类型字符串。
BYTEA/BIT 不被统一重标为 TEXT，TEXT 结果丢弃输入 varchar/char 的 typmod。
原生不透明回调不作为 UNKNOWN 字面量执行或强制解析；真实调用次数由独立计数器检查。
JSONB/TSVECTOR 的结构化执行另有开放问题，见下表，不由本项冒充实现。

协议参数类型来自现有绑定器选择的拼接输入 codec，并以不可变 SQL 源位置对应实际
wire 参数。显式 OID 保持优先，不为自定义类型猜 OID；发布推断前重新验证完整声明。
物理表的单个取反目标仅接入既有 AST 计划和纯描述器，限定为无函数/SRF/子查询的基本
位串表达式，并排除 CTE、集合、分组、HAVING、窗口和锁定；保留原有表/列权限检查和快照。
这不是开启任意物理 ProjectSet、完整参数约束求解或重构全局 carrier。
