# R325：原生查询默认绑定未解析实际内建类型

状态：无回调原生类型声明已修正并完成下述有限验证；总清单仍未完成。

## 问题与修复方法

`prepareQuery(sql,{},{})` 未提供 declaredType 回调时，只用拼写归一化，
不解析真正类型。`pg_catalog.bpchar` 与 `character` 被当成不同类型，
CHAR 数组出现错误的 42804；合法声明没有实际 OID，不存在的引号别名
也能被带 AS 别名的投影错误接受。

默认路径改用既有 `resolveDeclaredTypeName` 的纯内建模式，取真实
typeName/typeOid，继续由绑定器现有逻辑保存 modifier。它使用共享的
只读内建目录定义，不初始化目录、不扫描行、不执行表达式，也不读取
环境连接的 search_path。调用方提供 declaredType 时，仍原样优先使用
该回调的类型、OID、modifier；用户类型由该元数据所有者解析，不能
把其他 schema 的同名类型当成内建。

内部 `"char"`（OID18）与 SQL CHAR/BPCHAR（1042）保持区别。真正的
`pg_catalog."int4"` 等物理名有效，`pg_catalog."integer"` 等引号 SQL
别名不存在；数组物理 OID 及实际不存在的数组类型错误都保留。
本项不改变规划常量、REGTYPE/JSON 载体、窗口/派生查询或其他暂缓模块。
