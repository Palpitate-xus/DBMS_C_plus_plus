# R333：BIT/VARBIT 混合输入错误拒绝共同类型

状态：有序共同类型及其嵌套隐式转换已修复，并完成下述有限验证；独立失败和用户暂缓项仍保留。

resolveValuesResultType接受数值、字符串、日期及部分网络类型，却缺少
BIT/VARBIT同类别的共同类型路径。数组连接、混合数组构造和array_cat
因此错误返回42883/42804。两种位串类型有双向隐式转换；共同类型应
保留首个已知输入，不能一律转VARBIT或套用BIT(1)显式默认宽度。

修改方法：在已有共同类型入口纳入真实BIT/VARBIT家族，使用现有有序
隐式转换图；NULL/UNKNOWN跳过但不根据值推断类型，不改常量规划载体。
冻结965完整协议请求，原R335的777请求与期望为精确前缀；新增输入顺序、
不同元素长度、NULL、嵌套/下界数组、混合标量、参数、空结果和真实行。
原生88个实际PG SQL还验证真实绑定描述、求值，以及原生共同类型API。

R334写入路径及所有既有用户暂缓模块保持不动。本项不修复R332数组函数
参数转换/描述、R336显式BIT数组CAST或其他独立错误；必须保留真实失败。
过程证据：/tmp/dbms-r333-bit-common-type.ECwcekDh/。
只本地commit，不push、不启用Actions；原273总清单未完成。

## 实现与实际验证

真实BIT/VARBIT输入通过现有selectCommonType有序隐式转换图，保留首个
已知类型，不因VARBIT是preferred就覆盖双向隐式转换的首选输入。
补齐该共同类型转换的嵌套数组执行：BIT目标接收VARBIT子数组时使用
已经求值的RuntimeCell隐式转换，不再用显式BIT(1)截断。原有BIT[]
直通、其他类型、显式CAST、存储写入、规划器、公共头和Main均不修改。

初版只有准入修改时，新增嵌套用例真实返回`{{01},{0}}`而非PG的
`{{01},{001}}`；该候选未接受。补齐后，初版到最终版恰好3个请求
变化且只有data字段改变，全部匹配PG。初版全部失败日志保留，不从
测试中删除这条用例，也不接受“能够执行但值错误”的结果。
