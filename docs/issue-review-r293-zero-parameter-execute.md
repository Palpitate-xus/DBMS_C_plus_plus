## 两个错误

```sql
PREPARE zero_args AS SELECT 7 AS plain;
EXECUTE zero_args(1);
EXECUTE zero_args();
```

真实 PostgreSQL 18.6 在第二条返回 7、第三条报 42601；当前两侧产品反而
第二条报 42601、第三条返回 7。普通名称也可复现，并非 R292 美元符别名特有。
Main 当前先按文本提取括号内容，再一律作 values.size() == parameterTypes.size()
比较；空括号与根本没有括号被视作同样空参数列表。两处都需要修复。

| 场景 | PostgreSQL 18.6 | 当前两侧产品 |
|---|---|---|
| 零参数，省略括号 | 返回 7 | 返回 7 |
| 零参数，额外 1 个或 2 个表达式 | 返回 7 | 42601 |
| 零参数，额外表达式为 1/0 | 返回 7，不求值该表达式 | 42601 |
| 零参数，未定义列/函数或含子查询 | 这些合法语法的额外表达式不绑定、不求值，返回 7 | 42601 |
| 零参数，额外 `$0` / `$1`、数组、带逗号字符串或注释 | 返回 7 | 42601 |
| 空括号 `EXECUTE zero_args()` | 42601 | 错误返回 7 |
| 尾随逗号、仅逗号或裸 `SELECT 1` 作为参数 | 42601 | 42601 |
| 声明了 integer 类型但查询未引用它 | 仍要求 1 个参数，正确值返回 7；少/多参数报 42601 | 与参考相同 |
| 上述已声明但未使用的参数传入 1/0 | 22012 | 22012 |
| 真正 `$1` 语句 | 正确参数返回 5；少/多参数 42601，1/0 为 22012 | 与参考相同 |
| 错误后连接及 DEALLOCATE | 可继续使用 | 可继续使用 |

13 是观察差异数，不是独立 bug 数。源码问题包含错误的零参数数量分支以及
未区分空括号的语法问题；其余输入扩大兼容性与错误阶段的证据，未声称整个
EXECUTE grammar、所有 prepared statement 生命周期或系统崩溃恢复已覆盖。
