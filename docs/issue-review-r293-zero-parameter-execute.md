# R293：EXECUTE 原始参数语法、零输入与求值边界

状态：本项有限修复已通过下述正式构建、相邻回归及 scoped UBSan。
原 273 条总清单仍未整体完成，明确用户暂缓项保持暂缓。

| 缺陷 | 影响 | 修复方法 |
|---|---|---|
| 零输入语句仍严格比较实参数量 | 合法额外表达式被错误拒绝，未遵循 PG18 跳过其绑定/求值的规则 | 只在 PostgreSQL 括号形式且真实声明输入数为零时忽略额外参数；非零及声明未使用输入保留检查 |
| 空括号、缺失实参与部分非法表达式未完整检查 | `EXECUTE q()` 等非法语句可能成功；错误优先级也可能落到语句名查找 | 新 ExecuteStmt 由解析器拥有原始参数语法，先检查语法再查找已准备语句 |
| 前端将 sqlProcessor 改写结果交给参数解析 | ARRAY/ANY、CASE 的原始结构丢失，合法数组成为错误列引用，非法 CASE 也可能被改成有效调用 | EXECUTE 分派传递 effectiveRawSql，原始表达式字节由命令 AST 保存，不再用文本逗号重拆 |
| 参数语法和语义分析混用 | 忽略的未知列/函数、`$0`、DEFAULT、零列子查询等可能提前报错或求值 | 专用、可重入恢复的语法上下文；语法 AST 不生成 `$0` 的实际 Bind 槽位，返回值只保存原表达式文本 |

流程为：原始 SQL → ExecuteStmt 语法 → 已准备语句查找 → 按真实声明数量决定是否绑定、求值参数。
两侧保留非零输入的数量、类型和求值错误，也保留旧项目 `EXECUTE ... USING` 入口。
语法检查覆盖分隔符、实参缺失、CASE 必需关键字、表达式必要子节点、子查询及
合法命名/VARIADIC 形式；普通 SELECT 的 `$0` 仍不能变成合法输入。
新增一个命令 AST 类，已有 AST 类布局、磁盘格式、Main 的其他执行所有权机制未改。

[PostgreSQL 18 EXECUTE 文档](https://www.postgresql.org/docs/18/sql-execute.html)及独立
PostgreSQL 180006 实例共同作为参考。这里的零输入语义不能推广到已声明但未使用的参数：
后者仍需匹配输入数量并实际求值，`1/0` 仍报 22012。

## 两个错误

```sql
PREPARE zero_args AS SELECT 7 AS plain;
EXECUTE zero_args(1);
EXECUTE zero_args();
```

真实 PostgreSQL 18.6 在第二条返回 7、第三条报 42601；当前两侧产品反而
第二条报 42601、第三条返回 7。普通名称也可复现，并非 R292 美元符别名特有。
Main 当前先按文本提取括号内容，再一律作 values.size() == parameterTypes.size()
比较；空括号与根本没有括号被视作同样空参数列表。两处都需要修复。
